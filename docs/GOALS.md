# 專案目標

## 原始需求（使用者原文）
1. 以 rust 開發，需要有簡易 cmd 跟 tui，另外要有 web 管理介面
2. 基本架構為三大模塊：1.sip 核心引擎, 2.fax-in 模組, 3.fax-out 模組
3. sip 核心引擎可以從 sipress 專案的核心中抽取可用部分，這部份未來可能會變成獨立專案
4. 先做 fax-in，fax-out 未來再考慮
5. 先預設來源端是 voip gateway（sonus、audiocode...）
6. 先預設是 T.38（G.711 passthrough 為備援方案）
7. 開發過程中需為專案做測試，測試方案為使用 SpanDSP 做模擬 fax 進線
8. 傳真結果及設定需存在 DB，本機預設 SQLite，但須支援常見 DB 如：MSSQL、MySQL/MariaDB、PostgreSQL
9. 程式期望部署方式為解壓縮目錄即可使用，應採用靜態編譯（RHEL 9/10）

## 追加要求

## 來源端資訊更新（2026-10-20）
- 經使用者向資深同事確認：前端對接的是**中華電信 CS210**，傳真以 **T.38**（T.30 跑在 T.38 之上）送達。
- 影響：
  - 首要互通對象從「企業 gateway（Sonus、AudioCodes）」改為**中華電信 CS210**，gateway 相容性仍然保留。
  - 以下細節待確認：
    - 是否需要 REGISTER 和 digest 驗證
    - T.38 是在初始 INVITE 就帶上，還是透過 re-INVITE 切換
    - 由哪一方發起 re-INVITE
    - 使用的傳輸協定
    - 中間是否有 SBC
    - T.38 參數（version、UdpEC、RateManagement、MaxDatagram）
  - 使用者已確認：對方 **IP 固定**；傳輸**應該是 UDP**；**沒有規格文件**。
  - 決策：**保留彈性，兼容各種情形**（見 docs/design/sip-core.md 第 9 節）。
    - REGISTER 可以開關。
    - 來源 IP 白名單。
    - T.38 三種建立路徑都支援。
    - 可設定各家業者的 trunk profile。
    - 內建 SIP 和 T.38 擷取，用來在第一通實際來電時收集資料。
  - 取得實際的 SIP/T.38 pcap 之後，納入 M6 的回歸測試集，並據此修正預設參數。

## 使用者需求：傳真紀錄、預覽與清整（2026-10-21）
### 需求原文（由使用者轉述的終端客戶需求）
> 你需要收傳真，寫資料表，並且產生有 tif 傳真檔案，最好還有個線上預覽的 png。
> 資料表要記錄：ID，進線號碼 ANI，撥打號碼 DNIS，進線時間，掛線時間，掛線方向，掛線原因，通話長度，傳真接收狀態，傳真檔路徑，傳真檔大小，傳真檔頁數，備註（讓座席可以輸入）。
> 介面要支援已讀未讀，且可以自行調整切換。
> 要有可以設定的清整機制，資料與檔案保留多久。

### 已確認的決策
| 項目 | 決策 |
|---|---|
| 已讀/未讀 | **全體共用**。一份傳真只有一個已讀狀態，任何座席開啟或手動切換都會生效，介面也可以切回未讀。要記錄最後一次由誰、在什麼時候切換 |
| 清整機制 | **資料和檔案分開設定**。例如傳真檔和 PNG 保留 N 天後刪檔，資料表紀錄保留 M 天（M ≥ N）。刪檔後紀錄保留，並標記「檔案已清除」 |
| PNG 預覽 | **開啟時才產生**。第一次預覽時從 TIFF 轉出每頁的 PNG 並快取，快取隨清整機制一起刪除 |
| 開始時機 | 先記錄，等使用者說開始再做（M3/M4） |

### 欄位對應（Opus 草案，M3 設計時定案）
| 需求欄位 | 來源 / 定義 |
|---|---|
| ID | 自增主鍵，另存 SIP Call-ID 以便對照擷取記錄 |
| 進線號碼 ANI | 預設取 `P-Asserted-Identity` 的 user 部分，沒有的話取 `From` 的 user 部分。可依 trunk 設定優先順序，因為 CS210 的行為未知 |
| 撥打號碼 DNIS | 預設取 Request-URI 的 user 部分，沒有的話取 `To` 的 user 部分。可依 trunk 設定（例如 Diversion） |
| 進線時間 | 收到 INVITE 的時間 |
| 掛線時間 | 收到或送出 BYE（或 CANCEL、失敗回應）的時間 |
| 掛線方向 | `remote`（對方掛斷）、`local`（我方掛斷）、`system`（逾時、錯誤、拒接） |
| 掛線原因 | 整理過的原因碼加上說明文字，例如正常完成、對方掛斷、T.38 被拒、T.30 失敗（附 T.30 結果碼）、無媒體埠、逾時 |
| 通話長度 | 從 200 OK 到掛線，單位秒 |
| 傳真接收狀態 | `received`（完整收到）、`partial`（部分頁面）、`failed`（失敗）、`no_fax`（沒有傳真訊號，例如一般電話） |
| 傳真檔路徑、大小、頁數 | TIFF 的路徑、bytes 和頁數。PDF 的路徑另外存一個欄位 |
| 備註 | 座席可以編輯的文字欄位，記錄最後修改者和時間 |
| 已讀 | 布林值，加上最後切換者和時間 |
