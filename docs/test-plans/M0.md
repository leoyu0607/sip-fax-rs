## 2. 測試案例

### 建置與發佈（主 workspace）
| ID | 案例 | 步驟 | 預期結果 |
|---|---|---|---|
| B01 | 格式與 lint | `cargo fmt --check`；`cargo clippy --workspace --all-targets -D warnings` | 無錯誤 |
| B02 | 靜態連結 | 以 zigbuild 建置 x86_64 和 aarch64 的 musl 版本，再執行 `file` | 輸出包含 `statically linked` |
| B03 | 解壓即用 | 在 Rocky 9 和 Alma 10 容器中解壓 tarball，執行 `./sip-faxd --version` | exit 0；輸出等於 `sip-faxd <Cargo version>` |
| B04 | 禁用 TLS 函式庫 | `cargo deny check` | 通過；相依圖中沒有 `openssl-sys` 和 `native-tls` |
| B05 | CLI stub 行為 | 執行 `sip-faxd serve`（整合測試，用 `CARGO_BIN_EXE_sip-faxd`）| exit code 2；stderr 包含 `not implemented` |

### SpanDSP 模擬環境（tools workspace，在 Rocky 9 容器中執行）
| ID | 案例 | 預期結果 |
|---|---|---|
| S01 | `spandsp-sys` 以 pkg-config 連結 SpanDSP ≥ 3.1 | 建置成功。找不到 SpanDSP 時，build.rs 給出明確錯誤並指向 `scripts/e2e-docker.sh` |
| S02 | FFI 生命週期 | `t38_terminal_init`/`free` 和 `fax_init`/`free` 各重複 100 次：回傳非 null、不 crash，RSS 不持續增長（成長量 < 1 MiB）|
| S03 | 測試頁產生器 | 產生 N 頁 bilevel TIFF（寬 1728，解析度 204×98 和 204×196）。以獨立的 TIFF 讀取器驗證頁數、寬、高、解析度，並以 `tiffinfo` 交叉驗證 |
| S04 | T.38 loopback，1 頁 | caller 送 1 頁，answerer 接收。雙方 phase E 完成碼都是 `T30_ERR_OK`(0)，收到的 TIFF 為 1 頁、寬 1728 |
| S05 | T.38 loopback，多頁 | 送 3 頁，收到 3 頁，每頁尺寸與來源一致 |
| S06 | T.38 loopback 加 ECM | 雙方都開 ECM，結果與 S04 相同 |
| S07 | G.711 音訊 loopback | 雙方以 `fax_init` 每 160 個 sample 交換一次，結果與 S04 相同（為 M5 打底）|
| S08 | 錯誤路徑 | caller 的 tx 檔案不存在時，caller 的完成碼不等於 0。模擬時間上限內一定要結束，不可以卡住 |
| S09 | 封包遺失注入 | 以固定 seed 對每一份副本丟 5% 封包。在 SpanDSP 冗餘下仍完成 1 頁；並記錄丟包統計，斷言確實丟過封包 |
| S10 | 確定性與速度 | 使用模擬時鐘（不 sleep）。S04 的 wall time < 30 秒；同一 seed 連跑兩次，封包序列的 hash 相同 |
