# M5 測試計畫：G.711 passthrough（fax-modem）

- 撰寫：Opus（2026-10-23）
- 執行：Sonnet
- 審核：Opus
- 需求：`docs/GOALS.md` 第 6 點（T.38 為預設，G.711 passthrough 為備援）、第 23 行（數據機純 Rust 自行實作，SpanDSP 只用在測試端）；`docs/ROADMAP.md` M5 完成標準「fax-sim 以 G.711 模式送傳真，可以成功接收」。
- 設計決策：ADR-061（本計畫 §0 為摘要）
- 2026-10-23 使用者決定：① 高速數據機只做到 V.29（9600 bit/s），**不做 V.17**；② `t38_policy = "auto"` 時對方在 audio 上直接送 CNG，仍先由我方試 T.38 re-INVITE，被拒才改走 G.711。

## 0. 設計摘要

### 0.1 分層

```
RTP（G.711 PCMU/PCMA，20 ms）
  └ sip-core::rtp     RtpPacket（從 sipress 抽取並修正 decode）、g711 編解碼
fax-in::audio         jitter buffer、RTP 收送與 20 ms pacing、AudioSession（取代 T.38 的 t38session）
  └ fax-in::audioengine（sans-IO，虛擬時鐘）：8 kHz PCM ⇄ t30::Event / t30::Action
       └ fax-modem（純 DSP、sans-IO、不依賴任何 fax 以外的 crate）
            tone      CNG 偵測（1100 Hz）、CED 產生（2100 Hz）、能量／靜音偵測
            v21       V.21 第 2 頻道 FSK 300 bit/s（1650/1850 Hz）收與送
            hdlc      flag、bit stuffing、FCS-16；收端回報 frame 與 FCS 結果
            v27ter    2400/4800 bit/s 收（DPSK）
            v29       7200/9600 bit/s 收（QAM）
            common    AGC、時脈回復、載波回復、適應性等化器、scrambler
t30（不變）           同一個 Receiver，T.38 與 G.711 共用
```

- **t30 不改**：T.30 收端已經和傳輸無關（`t30/src/lib.rs` 註明可由 G.711 前端驅動）。音訊引擎看到自己交給 t30 的 DCS 時，以 `t30::Dcs` 解析出數據機與速率，切換高速收端；這與 T.38 引擎從 indicator 得知數據機的位置對等。
- **只收不送高速**：收傳真只需要高速數據機的「收」；我方只送 CED 與 V.21（DIS、CFR、FTT、MCF、RTN、DCN 等）。
- **DIS 只宣告 V.27ter 與 V.29**（沿用 `t30::Modems`；不做 V.17，使用者決定）：對方只能選 9600 以下，T.30 的協商會自動處理。
- **半雙工**：我方送 V.21 的期間與之後 75 ms，收端忽略輸入（自己的回音不會被當成對方的訊號）。
- **進入 G.711 的條件**（`fax-in` controller 現有政策延伸）：對方拒絕 T.38 re-INVITE（488／415／606、或 `m=image` port 0）、或 `t38_policy = "audio-only"`。對方在 audio 上直接送 CNG 而沒有 re-INVITE 時，`auto` 照現行政策在 `initiate_after_secs` 由我方發 T.38 re-INVITE，被拒才走音訊（使用者決定）；這段等待期間音訊引擎已在收（CNG、V.21 不會漏掉）。原本記為 `g711_passthrough_unsupported` 的情況改為走音訊。
- **清潔室實作**：演算法依 ITU-T V.21、V.27ter、V.29、T.30、G.711 規格自行撰寫；不參考、不複製 SpanDSP 原始碼（授權與 GOALS 的要求）。SpanDSP 只當測試對照。

## 1. 共通規則

- 測試函式以案例 ID 開頭。DSP 測試全部是確定性的：雜訊、抖動、遺失都用固定 seed 的 PRNG，每個案例至少 3 個 seed。
- **獨立對照**：每一個數據機與協定都要有一個不是我們寫的對照，在 Rocky 9 測試映像（Docker）中執行：
  - 各數據機的送端：SpanDSP `fsk_tx`（V.21）、`v27ter_tx`、`v29_tx`（`tools/fax-sim` 的 `spandsp-sys` 補上這些 FFI；只在測試）
  - 我方 V.21 送端的對照收端：SpanDSP `fsk_rx`
  - HDLC：SpanDSP `hdlc_tx` 產生的位元流
  - 整通傳真：SpanDSP `fax_state`（`fax_sim::spandsp::FaxModem`），可強制數據機
  - G.711：ITU-T G.711 的編碼表（A-law、μ-law 各 256 個值逐一比對）；SpanDSP `alaw_to_linear`／`ulaw_to_linear` 交叉比對
- **影像一律逐像素比對**（沿用 M2：libtiff 與 poppler 兩個獨立來源）。
- **涵蓋率**：`fax-modem` ≥ 85%（協定 crate）；`sip-core` 維持 ≥ 85%（含 `rtp`）；`fax-in` 維持 ≥ 70%。CI 的 coverage job 納入 `fax-modem`。
- **proptest**：每個收端（tone、v21、hdlc、v27ter、v29、jitter buffer、RtpPacket）餵任意輸入不 panic、不無限迴圈、記憶體有上限。
- **fuzz 目標**：`rtp_decode`、`hdlc_deframe`、`audio_rx`（任意 i16 樣本流進音訊引擎的收端）。nightly fuzz workflow 納入。
- **訊號條件的參數**：雜訊以 AWGN 指定 SNR（dB，相對於訊號功率）；電平以 dBm0（G.711 的 0 dBm0 = 3.14 dBov 的正弦）；時脈偏差以 ppm（送端取樣率相對 8000 Hz）；相位抖動與頻率偏移只在高速數據機的強健性案例使用。
- **效能**：每個收端在 x86_64 musl release 上處理 1 秒音訊的 CPU 時間 < 50 ms（同時 30 通的餘裕），以 `criterion` 量測並寫進報告（不設 CI 門檻）。

## 2. RTP 與 G.711（G，M5a）

| ID | 案例 | 預期 |
|---|---|---|
| G01 | μ-law、A-law 解碼：256 個碼值 | 與 G.711 表完全相同；與 SpanDSP 相同 |
| G02 | 編碼：所有 16-bit 線性值 | 與 SpanDSP 相同；解碼再編碼回到同一碼值（idempotent） |
| G03 | `RtpPacket` decode：CSRC（0–15 個）、extension、padding、marker、版本不是 2 | 欄位正確；payload 不含 padding；錯誤輸入回 `Err`（sipress 原本的錯誤在 `docs/sipress-extraction.md` 記錄並有對應案例） |
| G04 | `RtpPacket` encode → decode round-trip（proptest） | 相等 |
| G05 | SDP 協商：對方只給 PCMA、只給 PCMU、兩者都有、都沒有、有 telephone-event | 選擇依 trunk 設定的偏好；都沒有時 488；telephone-event 忽略 |

## 3. Jitter buffer 與 RTP 收送（J，M5a／M5e）

| ID | 案例 | 預期 |
|---|---|---|
| J01 | 依序到達、固定 20 ms | 輸出與輸入逐樣本相同，延遲等於設定的起始深度 |
| J02 | 抖動 ±40 ms（均勻）、亂序 5% | 輸出逐樣本相同（沒有遺失時不插入任何東西） |
| J03 | 遺失 1%、3%（獨立與連續 3 包） | 遺失的 20 ms 補靜音並回報 `Gap(samples)`；之後的樣本對齊（以 RTP timestamp 定位，不以到達時間） |
| J04 | seq 與 timestamp 繞回 | 正確排序，不誤判缺口 |
| J05 | SSRC 改變（對方切換 media）、timestamp 大跳 | 重新同步，回報一次 `Resync` |
| J06 | 送端 20 ms pacing（虛擬時鐘） | 每 20 ms 一包、timestamp 每包 +160、seq +1；負載高時不累積延遲（落後時合併送出，不丟） |
| J07 | 時脈偏差 ±200 ppm 持續 10 分鐘 | buffer 深度維持在設定範圍內（緩慢丟棄或補一個樣本），不溢位 |

## 4. 訊號音與能量（N，M5a）

| ID | 案例 | 預期 |
|---|---|---|
| N01 | CNG：1100 Hz、0.5 s on / 3 s off，電平 −10 到 −43 dBm0，SNR 20 dB | 每個 on 段都偵測到，延遲 < 400 ms |
| N02 | 非 CNG：1000 Hz、1200 Hz、語音樣本（錄音檔）、DTMF、撥號音 | 不誤判 |
| N03 | CED 產生 | 2100 Hz ± 15 Hz、長度 2.6–4.0 s（預設 3.0 s）、之後 75 ms 靜音；電平依設定；以 SpanDSP `modem_connect_tones_rx` 偵測得到 |
| N04 | 能量偵測：訊號開始／結束 | 門檻 −43 dBm0；開始與結束的判定延遲在 ±10 ms 內（對應 T.38 的 `NoSignal`） |

## 5. V.21 與 HDLC（V、H，M5b）

| ID | 案例 | 預期 |
|---|---|---|
| H01 | HDLC 送端：flag、bit stuffing（含連續 5 個 1 的邊界）、FCS-16 | 與 SpanDSP `hdlc_tx` 位元流相同 |
| H02 | HDLC 收端：SpanDSP 產生的位元流（多個 frame、前導 flag 1 s） | frame 內容與 `fcs_ok` 正確 |
| H03 | 錯誤：FCS 錯、abort（7 個 1）、長度不足、超長 | `fcs_ok = false` 或丟棄；不 panic（proptest、fuzz `hdlc_deframe`） |
| V01 | V.21 收：SpanDSP `fsk_tx` 送 DIS/DCS/CFR 等 frame，電平 −10 到 −43 dBm0，SNR 15–30 dB | frame 全部正確（每個條件 200 個 frame，FCS 錯誤率 0；SNR 12 dB 時 ≤ 1%） |
| V02 | V.21 收：時脈偏差 ±100 ppm、頻率偏移 ±10 Hz | 同 V01 |
| V03 | V.21 送：我方送 frame，SpanDSP `fsk_rx` 收 | 全部正確；頻率 1650／1850 Hz ±1 Hz；前導 flag 長度 1 s ± 15%（T.30 5.3.1） |
| V04 | 前導偵測 → `RxSignal::V21Preamble`、訊號結束 → `NoSignal` | 事件時間與實際差 < 30 ms |
| V05 | 半雙工：我方送 V.21 時，輸入是我方訊號的回音（−10 dB、延遲 0–60 ms） | 不產生任何收到的 frame；送完 75 ms 後恢復收 |

## 6. 高速數據機收端（A：V.27ter，B：V.29）

每個數據機、每個速率，用 SpanDSP 對應的 `*_tx` 送 TCF（全 0，1.5 s）與隨機資料（以固定 seed 的 PRNG 產生，前後各有 training 與結束），我方收端解出位元後比對。

| ID | 案例 | 預期 |
|---|---|---|
| A01／B01 | 乾淨訊號，電平 −10 dBm0，各速率（V.27ter 2400／4800、V.29 7200／9600） | BER = 0（10⁶ bit）；training 偵測到 → `RxSignal::Training`；結束 → `DataEnd` |
| A02／B02 | 電平 −10 到 −43 dBm0 | 同上 |
| A03／B03 | AWGN：V.27ter 4800 SNR 15 dB、V.29 9600 SNR 20 dB（另一組較低 SNR 只記錄 BER 曲線） | BER ≤ 10⁻⁵ |
| A04／B04 | 時脈偏差 ±100 ppm、頻率偏移 ±7 Hz | BER ≤ 10⁻⁵（SNR 同 03；V.27ter 4800 為 03 的 SNR＋2 dB，在 03 的 SNR 時 ≤ 10⁻⁴，ADR-064） |
| A05／B05 | G.711 量化（訊號先經 μ-law 與 A-law 編解碼） | 同 04（實際線路一定經過 G.711） |
| A06／B06 | RTP 遺失 1 包（20 ms）落在資料中段 | 收端不卡住：遺失後重新收斂或回報 `DataEnd`＋錯誤，t30 以 bad_lines 計；之後的 V.21 照常收 |
| A07／B07 | TCF 判定：送全 0 與送含錯的 TCF | 引擎以 t30 的 TCF 門檻得到 CFR／FTT（與 T.38 相同的判定） |
| A09／B09 | proptest：任意樣本流（雜訊、靜音、其他數據機） | 不 panic；不產生 `Training` 之外的假事件（雜訊不誤判為 training，1 小時白雜訊誤判次數 0） |
| B10 | 對方先試 V.17（我方 DIS 沒有宣告，但有的機器仍會送）| 不誤判為 V.29 training；t30 依 DCS 回應（DCS 指定我方沒有的數據機時以 DIS 重新協商） |

## 7. 音訊引擎＋t30，與 SpanDSP 整通互打（M，in-process，Docker）

`fax_sim::spandsp::FaxModem` 當發送端（calling，帶 TIFF），我方 `audioengine` 當收端，以 8 kHz 樣本區塊互接（沿用 `audio_loopback` 的結構），中間可插入通道模型（電平、AWGN、時脈偏差、G.711 量化、20 ms 遺失）。

| ID | 案例 | 預期 |
|---|---|---|
| M01 | SpanDSP 強制 V.27ter 4800，1 頁 standard | 收下；逐像素相同；`T30Result` 的 modem = V.27ter、rate = 4800 |
| M02 | 強制 V.29 9600，3 頁 fine，MH／MR | 同上 |
| M03 | 不強制：SpanDSP 依我方 DIS 選擇 | 選 V.29 9600（DIS 沒有 V.17） |
| M04 | TCF 失敗降速：通道 SNR 讓 9600 的 TCF 失敗 | 我方回 FTT，SpanDSP 降到 7200 或 4800 後成功 |
| M05 | 頁面中有 1 包遺失 | 該頁 bad_lines ≥ 1 且符合 t30 門檻時 MCF（否則 RTN）；其餘頁逐像素相同 |
| M06 | 多頁 MPS／EOP、對方重送 EOP（我方 MCF 遺失） | 與 T.38 路徑相同的行為（F1 的修正在音訊路徑同樣成立） |
| M07 | ECM（M3d，預設關閉）：開啟時 V.29 ECM 收 | 收下；逐像素相同 |
| M08 | 對方在 CED 期間就送 CNG、或不等 CED 直接送 DCS 前的 V.21 | 照樣收下 |

## 8. fax-in 整合與端到端（E，M5e，Docker：fax-sim SIP＋SpanDSP 音訊經 RTP 打 `sip-faxd serve`）

`tools/fax-sim` 的 SIP UAC 加上 G.711 模式：SpanDSP `FaxModem` 的樣本以 RTP（PCMU 或 PCMA）送出與接收，20 ms pacing。

| ID | 案例 | 預期 |

| E02 | 對方拒絕 T.38（re-INVITE 回 488）→ 改走 G.711 | 同 E01；`result.json` 記錄「T.38 被拒，改用 G.711」；不再出現 `g711_passthrough_unsupported` |
| E03 | PCMA | 同 E01 |
| E04 | 網路：抖動 ±30 ms、遺失 0.5% | 收下；有遺失的頁 bad_lines 在 t30 門檻內 |
| E05 | 接收中狀態與即時頁數（M3）、Web 的 `fax.progress`（M4） | 與 T.38 相同（每頁更新） |
