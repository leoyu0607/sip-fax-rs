# M3 測試計畫：紀錄、預覽、清整、投遞、ECM

- 撰寫：Opus
- 執行：Sonnet
- 審核：Opus
- 規格：`docs/design/m3-store.md`

## 0. 共通規則
- 測試函式以案例 ID 開頭。凡是和時間有關的邏輯，例如清整、重試、接收中狀態，都必須能注入時鐘，不可以真的等待。
- **DB 行為測試只寫一份，在四種後端上各跑一次**，透過 `SIP_FAXD_TEST_DB=<url>` 選擇後端：
  - 本機預設是 SQLite（檔案和 `:memory:` 各跑一次）。
  - CI 的新 job `db-matrix` 以 services 啟動以下容器，每個後端都要跑完全部的 S 案例：
    - `postgres:16`
    - `mysql:8.0`
    - `mariadb:11`
    - `mcr.microsoft.com/mssql/server:2022-latest`
- **覆蓋率門檻**：
  - `store`、`delivery` ≥ 80%。
  - `fax-in` 維持 ≥ 70%。
  - `t30` 維持 ≥ 85%。
- **獨立對照**：
  - PNG 以 libpng 或 ImageMagick（`pngtopnm` 或 `magick`）解碼，與 TIFF 做逐像素比對。
  - Email 以容器中的 MailHog（或 smtp4dev）接收後解析。
  - ECM 的互通對象是 SpanDSP，ECM 開啟。

## 1. Store（S）（四種 DB 都要跑）
| ID | 案例 | 預期 |
|---|---|---|
| S01 | migration：空 DB、重複執行、DB 版本比程式新 | 建出所有表和索引；重複執行不會出錯；版本較新時拒絕並給出清楚的錯誤 |
| S02 | 接收中流程：INSERT receiving，更新頁數 1→2→3，finalize | 每一步讀回的欄位都正確；`ended_at` 和 `duration_sec` 正確 |
| S03 | 時間精度與時區 | 寫入毫秒級 UTC 後讀回完全相等；分別以 UTC+8 和 UTC 的 TZ 執行，結果一致 |
| S04 | 長字串與特殊字元：中文備註、4000 字、emoji、`'";--` | 原樣存取；超過上限時回錯誤；不會發生 SQL injection |
| S05 | `set_read`：切換、切回、記錄切換者 | 欄位正確；`list` 依 is_read 篩選的結果正確 |
| S06 | `set_note` 樂觀鎖 | 舊的 `expected_updated_at` 回 `Conflict`；新的成功 |
| S07 | `list`：組合篩選、keyset 分頁、上限 200 | 結果和順序正確；分頁不重複、不遺漏（含同一毫秒的資料）|
| S08 | 啟動時修正殘留的 receiving 紀錄 | 依頁數轉成 failed 或 partial，`hangup_code = shutdown` |
| S09 | 並行：10 個 task 同時 insert 和 update 不同紀錄，2 個 task 同時改同一筆的備註 | 不會遺失資料；備註衝突時只有一方成功 |
| S10 | `settings`：首次啟動從設定檔初始化，之後以 DB 為準 | 修改 DB 後重啟，不會被設定檔覆蓋 |
| S11 | DB 暫時無法連線（容器停止後再啟動）| 收傳真不受影響；寫入在連線恢復後完成；`db backfill` 能從 result.json 補回缺漏的紀錄 |

## 3. 預覽（P）
| ID | 案例 | 預期 |
|---|---|---|
| P01 | 整頁 PNG（standard 和 fine）| 用 libpng 解碼後與 TIFF 逐像素比對；standard 解析度的頁面高度變成兩倍，每一行重複兩次 |
| P02 | 縮圖 | 寬 300，高度依比例；以獨立的參考實作計算面積平均，誤差 ≤ 1 灰階 |
| P03 | 快取 | 第二次直接讀快取，不重新轉檔（以轉檔計數器驗證）；8 個並行請求只轉檔一次；轉到一半時中斷，不會留下半成品檔案 |
| P04 | 錯誤 | 頁碼超出範圍、檔案已清整、TIFF 損壞，都回明確的錯誤，不會 panic |

## 4. 清整（R）（注入時鐘）
| ID | 案例 | 預期 |
|---|---|---|
| R01 | 邊界：剛好在保留天數前後各 1 秒 | 只清除超過期限的 |
| R02 | 檔案清整 | 刪除 TIFF、PDF 和 PNG 快取；設定 `files_purged_at`；紀錄保留 |
| R03 | 紀錄清整 | 先刪除殘留檔案，再刪除紀錄和 delivery_attempts |
| R04 | 刪檔失敗（例如目錄唯讀）| 不設定 `files_purged_at`，記 error，下次重試成功 |
| R05 | receiving 的紀錄、`files_days = 0`、`records_days = 0` | 都不清除 |
| R06 | 路徑在 `data_dir` 之外（例如竄改過的 DB 資料）| 拒絕刪除並記錄 |
| R07 | `--dry-run` | 只計數，不刪除 |
| R08 | 批次處理：1200 筆到期 | 分 3 批完成，數量正確 |
