# M2 測試計畫：t38 / t4 / t30 / fax-in 收傳真

- 撰寫：Opus
- 執行：Sonnet
- 審核：Opus
- 規格：`docs/design/fax-stack.md`

## 0. 共通規則
- 測試函式以案例 ID 開頭。計時器測試一律用 paused time 或虛擬時鐘，斷言到毫秒且必須精確相等。
- **獨立驗證來源**：每一個協定或格式都至少要有一個不是我們自己寫的對照：
  - IFP 和 UDPTL：SpanDSP
  - T.4 和 TIFF：libtiff（`tiffcp`、`tiffcmp`、`tiffinfo`）
  - PDF：poppler（`pdfinfo`、`pdftoppm`）
  - T.30：SpanDSP `t38_terminal`

  這些工具都要裝進 Rocky 9 測試映像。
- **影像比對一律逐像素比較**：把來源 bitmap 和收到的結果都轉成 1-bit raster 後完全比對。只有在有注入封包遺失、且是 non-ECM 的案例，才允許以 bad_lines 的範圍斷言。
- **涵蓋率**：t38、t4、t30 都要 ≥ 85%，fax-in 維持 ≥ 70%。CI 的 coverage job 要納入這幾個 crate。
- 每個 crate 都要有 proptest，以及以下 fuzz 目標：`ifp_decode`、`udptl_decode`、`t4_decode`。

## 1. IFP（I）
| ID | 案例 | 預期 |
|---|---|---|
| I01 | SpanDSP 黃金向量（從 loopback 擷取，涵蓋 non-ECM、ECM、v0、v3 會話中出現的所有封包）| 解碼成功；重新編碼後與原始 bytes 完全相同 |
| I02 | 所有 Indicator、DataType 和 FieldType 組合，各個 version 都做 round-trip | 編碼後再解碼結果相等 |
| I03 | v0 遇到 v2+ 才有的型別 | 編碼端拒絕，解碼端回錯誤 |
| I04 | 截斷或格式錯誤的封包，以及 proptest 任意 bytes | 回錯誤，不會 panic |
| I05 | 長度 determinant 的邊界值（127/128、16383/16384）| 依 PER 正確編解碼 |

## 2. UDPTL（U）
| ID | 案例 | 預期 |
|---|---|---|
| U01 | redundancy 封包的編解碼（深度 0–4）| round-trip 相等；與 SpanDSP `udptl` 產生的 bytes 相同（若 SpanDSP 3.1 有提供 udptl API 就做 FFI 對照，否則記錄理由，並以 T.38 附錄的範例驗證）|
| U02 | FEC 編解碼，以及 XOR 補回 | 每個 span 內遺失 1 個封包時可以補回 |
| U03 | 接收端行為 | 順序交付；亂序在視窗內時重新排序；重複的丟棄；以 redundancy 補回；以 FEC 補回；無法補回時回報 `Gap`，之後繼續正常運作 |
| U04 | seq 繞回（65534 → 1）| 正確排序，沒有誤判成缺口 |
| U05 | proptest：隨機遺失、亂序、重複的序列 | 交付的序列沒有重複、順序正確，而且「交付的加上 Gap 計數的」正好等於「送出的」 |

## 3. T.4 / TIFF / PDF（F）
| ID | 案例 | 預期 |
|---|---|---|
| F01 | 用 libtiff 把 5 種測試頁（全白、全黑、棋盤、文字掃描樣式、隨機雜點）編碼成 G3-1D | 解碼結果與原 bitmap 逐像素相同 |
| F02 | 同 F01，改成 G3-2D（K=2 和 K=4）| 逐像素相同 |
| F03 | 同 F01，改成 G4（MMR）| 逐像素相同 |
| F04 | EOL 帶 fill bits、RTC、EOFB | 都能正確偵測，頁面在正確的行結束 |
| F05 | MH 資料中某一行損毀 | 在下一個 EOL 重新同步；損毀行以上一行替代；`bad_lines` 正確 |
| F06 | 我們的 MMR 編碼器 | 由 libtiff 解碼（`tiffcp -c none`），與原 bitmap 逐像素相同 |
| F07 | 多頁 TIFF 寫出 | `tiffinfo` 顯示頁數、解析度和 G4 正確；`tiffcmp` 和原圖比對相同 |
| F08 | PDF 寫出 | `pdfinfo` 的頁數和頁面尺寸正確；`pdftoppm -mono -r 204x(98 或 196)` 轉出的 raster 與原 bitmap 逐像素相同 |
| F09 | proptest 和 fuzz：任意 bytes 輸入解碼器 | 不 panic，行數有上限保護 |

## 4. T.30 接收端（R）（純狀態機，虛擬時鐘）
| ID | 案例 | 預期 |
|---|---|---|
| R01 | 表格驅動：所有狀態 × 所有事件 | 每一格的動作和下一個狀態都符合規格 |
| R02 | DIS 內容 | 依設定組合（調變、解析度、編碼）產生的 FIF 位元與 T.30 表 2 一致（逐 bit 斷言）|
| R03 | DCS 解析 | 涵蓋各速率、解析度、編碼、紙寬，以及擴充位元 |
| R04 | transferredTCF 判斷 | 全 0 且長度足夠時回 CFR；錯誤率超過門檻或長度不足時回 FTT；FTT 之後對方降速重試也能通過 |
| R05 | localTCF | 收到 DCS 後直接回 CFR |
| R06 | Phase D | MPS 回 MCF 並進入下一頁；EOP 回 MCF 並等 DCN；EOM 回到 Phase B；bad_lines 超過門檻時回 RTN |
| R07 | 計時器 | DIS 在 T4 重送 3 次後失敗；T2 和 T1 逾時，時間點精確 |
| R08 | 任何狀態收到 DCN | 正確結束；部分頁面依規格回報 |
| R09 | CRP | 重送上一個回應 |
| R10 | 收到 FCS-BAD 的 frame | 依 T.30 規則處理（不採用並等待重送），不會當成正常 frame |

## 5. 與 SpanDSP 直接以 IFP 互打（X）（不經 SIP，在 Rocky 9 容器中執行）
| ID | 案例 | 預期 |
|---|---|---|
| X01 | SpanDSP `t38_terminal`（caller）送給我們的 t30+t38，矩陣：頁數 1/3、解析度 standard/fine、SpanDSP 端強制 MH/MR/MMR、速率 4800/9600/14400 | 雙方完成碼都 OK；逐頁逐像素相同 |
| X02 | UDPTL 層注入 5% 遺失，redundancy 深度 3，用 5 個 seed | 全部成功，逐像素相同（redundancy 能補回全部遺失）|
| X03 | transferredTCF 對 localTCF | 兩種都成功 |
| X04 | T.38 version 0 和 3 | 兩種都成功 |
| X05 | SpanDSP 中途斷線，或 tx 檔案不存在 | 我方的結果碼正確反映失敗原因，沒有卡住 |
| X06 | 補完 M0 審核的追蹤項目：fax-sim 加入 UDPTL redundancy 模型（用我們的 t38 crate）| 讓 X02 能夠成立 |
