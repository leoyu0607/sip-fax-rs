# M4 測試計畫：設定入 DB、帳號、Web、TUI、CLI、服務管理

- 撰寫：Opus
- 執行：Sonnet
- 審核：Opus
- 規格：`docs/design/m4-web.md`

## 0. 共通規則
- 測試函式以案例 ID 開頭。凡是和時間有關的邏輯（session 過期、登入鎖定、憑證到期提醒、log 輪替、stop 等待），都必須能注入時鐘，不可以真的等待。
- DB 相關的行為測試沿用 M3 的 `db_case!`：本機跑 SQLite，CI 的 `db-matrix` 在四種伺服器 DB 上跑同一套。
- **不 mock store**；HTTP 測試對真正在本機監聽的 axum 伺服器發請求（`reqwest`），不是直接呼叫 handler。
- **涵蓋率門檻**：`web` ≥ 80%；`store` 維持 ≥ 80%（排除伺服器驅動，ADR-045）；`fax-in` 維持 ≥ 70%。前端以 vitest 的 statements ≥ 70%。
- **獨立對照**：
  - 憑證用 `openssl x509`（Docker 裡）解析，不用我們自己的程式碼驗證內容。
  - 密碼雜湊用另一個實作（例如 Python `argon2-cffi`，在 Docker 裡）驗證可互通。
  - 加密的秘密欄位用測試內獨立呼叫 `ring` 的 AES-GCM 解密，不呼叫被測函式。
- 安全相關的每個案例都要有**反向斷言**（應該被拒絕的請求確實被拒絕，並檢查狀態碼與 DB 沒有被改動）。

## 1. 執行設定入 DB（K）
| ID | 案例 | 預期 |
|---|---|---|
| K01 | 首次啟動：DB 沒有執行設定，設定檔有完整設定 | 全部匯入；`config_audit` 有一筆 `by = config-file`；之後讀回的設定與設定檔逐欄位相等（含 trunk 順序與路由順序） |
| K02 | 第二次啟動：設定檔的值已改 | DB 的值不變；log 有「已改由資料庫管理」的 warning，列出區段名稱 |
| K03 | `config import` 無 `--force` 而 DB 已有設定；有 `--force` | 前者拒絕且 DB 不變；後者覆蓋並記稽核 |
| K04 | `config export` 後再 `config import --force` 到空 DB | 往返後設定完全相同；預設輸出不含秘密，`--include-secrets` 才含 |
| K05 | 每個區段的驗證錯誤（例如 resolutions 為空、路由 `default` 不是最後一條、port_range 反向、未知 trunk preset） | `PUT` 回 422 並逐欄位列出錯誤；DB 與記憶體快照都不變 |
| K06 | 樂觀鎖：兩個管理員同時改同一區段 | 只有一方成功，另一方 409，回傳目前的 version |
| K07 | 熱套用：通話進行中修改該 trunk 的設定 | 進行中的通話繼續用舊快照（以 E2E 或 controller 測試驗證）；下一通用新設定 |
| K08 | 需要重啟的設定（`sip.bind`、`media.port_range`） | 回應標示 `restart_required`；`/status` 列出待生效的變更；重啟後生效且標示消失 |
| K09 | 修改 `trunks.register` | 舊的註冊先 un-REGISTER，再以新設定註冊（SIPp registrar 驗證） |
| K10 | 秘密欄位：寫入後 DB 中是 `enc:v1:` 格式；API 與 `config export` 預設都不回傳明文；稽核紀錄中是 `***` | 正確；以獨立的 AES-GCM 解密得到原值 |
| K11 | `secret.key` 遺失或內容錯誤 | 啟動成功；log 有 error；受影響的功能失敗並有明確原因；其他功能正常；重新輸入後恢復 |
| K12 | DB 連不上時 | 照舊使用記憶體快照收傳真；`PUT /config` 回 503；DB 恢復後可以修改 |
| K13 | M3 `settings` 表的清整天數在 migration 0002 後搬進 `retention` 區段 | 數值相同；四種 DB 都正確 |

## 2. 帳號與驗證（A）
| ID | 案例 | 預期 |
|---|---|---|
| A01 | 首次啟動沒有使用者 | 建立 `admin` 與 `conf/initial-admin-password`（權限 0600）；log 中**沒有**密碼；第一次登入被要求改密碼，改完後檔案被刪除 |
| A02 | 密碼雜湊 | argon2id、參數符合規格；以獨立實作驗證可互通 |
| A03 | 密碼規則：太短、與帳號相同 | 拒絕並回固定錯誤代碼 |
| A04 | 登入鎖定：連續 5 次失敗；第 6 次即使密碼正確 | 鎖 15 分鐘（注入時鐘）；時間到後可登入 |
| A05 | 帳號不存在 vs 密碼錯誤 | 錯誤代碼與訊息相同；回應時間差異 < 20%（各量 50 次取中位數） |
| A06 | 同一 IP 每分鐘超過 20 次 | 回 429 |
| A07 | Session 閒置過期、絕對上限 7 天 | 注入時鐘驗證邊界前後各 1 秒 |
| A08 | 登出、停用帳號、重設密碼 | 該使用者所有 session 失效，WebSocket 連線被關閉 |
| A09 | Cookie 屬性 | `HttpOnly`、`SameSite=Strict`；HTTPS 時有 `Secure`，HTTP 時沒有 |
| A10 | CSRF：缺少 `X-Sipfax-Csrf`、token 錯誤、`Content-Type` 不是 JSON | 一律 403，DB 不變 |
| A11 | 權限矩陣：規格 §2.1 每一列 × 兩種角色 × 未登入 | 表格驅動；允許的回 2xx，不允許的回 401／403 且 DB 不變 |
| A12 | 最後一個 admin 不能被停用或降級 | 回 409 |
| A13 | CLI：`user add/passwd/disable/enable/list` | 正確；`--password-stdin` 可用；操作記入稽核 |

## 3. REST API（W）
| ID | 案例 | 預期 |
|---|---|---|
| W01 | `GET /faxes` 篩選與分頁（沿用 M3 S07 的資料集） | 結果與 store 層一致；cursor 竄改時回 400 |
| W02 | `GET /faxes/{id}` | 欄位齊全，含投遞嘗試；不存在回 404 |
| W03 | 已讀切換 | 記錄切換者為登入的帳號；`fax.read_changed` 事件送出 |
| W04 | 備註衝突 | 409，回傳目前的備註、修改者與時間 |
| W05 | 預覽 PNG | 內容與 `Preview` 產生的檔案相同；`ETag` 相同時回 304；頁碼超出回 404；已清整回 410 |
| W06 | 下載 PDF／TIFF | bytes 與檔案相同；`Content-Disposition` 檔名安全（含中文時用 RFC 5987）；已清整回 410 |
| W07 | 路徑安全 | id 或頁碼帶 `..`、編碼過的斜線、超大數字，都回 400／404，不會讀到 `data_dir` 外的檔案 |
| W08 | 重新投遞 | 只有 `failed`／`giving_up` 的才會重排；新增一列 `pending`；agent 呼叫回 403 |
| W09 | `GET /status` | 通話數、註冊狀態、DB 狀態、待重啟設定都正確 |
| W10 | 錯誤格式 | 所有錯誤都是 `{"error": {"code", "message"}}`，不洩漏內部路徑或 SQL |
| W11 | 請求大小上限（例如 1 MiB）與逾時 | 超過時回 413；慢速請求被關閉 |

## 4. WebSocket（V）
| ID | 案例 | 預期 |
|---|---|---|
| V01 | 收一份 3 頁傳真（E2E） | 依序收到 `fax.created`、3 次 `fax.progress`、`fax.finalized`，`seq` 連續 |
| V02 | 斷線後帶 `since` 重連 | 補送缺少的事件，不重複 |
| V03 | `since` 超出緩衝範圍 | 收到 `resync` |
| V04 | 未登入、session 過期 | 握手被拒（401） |
| V05 | ping/pong 逾時 | 伺服器關閉連線（注入時鐘） |
| V06 | 100 個同時連線 | 每個都收到所有事件；一個慢的客戶端不會拖慢其他人（緩衝滿時中斷該連線） |

## 5. HTTP / HTTPS（H）
| ID | 案例 | 預期 |
|---|---|---|
| H01 | `scheme = https`，沒有憑證 | 產生自簽憑證；以 `openssl x509` 驗證：ECDSA P-256、有效期 825 天（±1 天）、EKU 含 serverAuth、SAN 含主機名稱、localhost、127.0.0.1 與 `tls_names`；私鑰 0600 |
| H02 | 第二次啟動 | 沿用同一張憑證（指紋相同） |
| H03 | 使用者提供的憑證與私鑰 | 使用該憑證；檔案不存在或不成對時啟動失敗，訊息清楚 |
| H04 | 到期前 30 天 | 自簽憑證：啟動時自動重新產生，log 有 warning 與舊指紋；使用者提供的憑證：不更換，log 有 warning（注入時鐘） |
| H05 | TLS 版本 | TLS 1.2／1.3 可連；TLS 1.1 以下被拒（以 `openssl s_client` 驗證） |
| H06 | `scheme = http` 且 bind 不是 loopback | 啟動 log 有 warning |
| H07 | 安全 header | 規格 §5.3 每一個都存在；HSTS 只在 HTTPS |
| H08 | 指紋輸出 | 啟動 log 印出的 SHA-256 指紋與 `openssl x509 -fingerprint -sha256` 一致 |

## 7. 服務管理、TUI、CLI（M）
| ID | 案例 | 預期 |
|---|---|---|
| M01 | `start` | 背景啟動、PID 檔與 flock；就緒後顯示 log；送 SIGINT 給前景程序後服務仍在執行 |
| M02 | `start -d`；已經在執行時再 `start` | 前者立即返回；後者回非 0 並說明 PID |
| M03 | 就緒逾時（例如 bind 失敗） | 顯示 log 最後 50 行，回非 0，不留下 PID 檔 |
| M04 | `stop` 時有一通傳真正在收（E2E） | 新 INVITE 回 503；等那通收完才結束；傳真完整（`received`） |
| M05 | `stop` 超過 `stop_timeout_secs`、`stop --force` | 通話被結束，已收的頁面寫出，`partial` + `shutdown` |
| M06 | `restart` | 等通話結束後重新啟動；PID 改變；設定與 session 都保留 |
| M07 | `status`：執行中／沒有執行 | 輸出內容正確；沒有執行時回非 0 |
| M08 | systemd 偵測 | 設定 `INVOCATION_ID` 時，start/stop 提示改用 systemctl 並回非 0；`--ignore-systemd` 可以略過 |
| M09 | SIGTERM 給 `serve` | 與 `stop` 相同的流程 |
| M10 | 控制 socket 權限 | 0600；其他帳號連線被拒（Docker 中以另一個 uid 驗證） |
| M11 | log 輪替：依大小、依日期、保留份數、gzip | 注入時鐘；舊檔可以用 `gzip -t` 驗證；輪替時不遺失 log 行 |
| M12 | `logs -f` | 輪替後仍繼續跟隨新檔 |
| M13 | TUI：以 ratatui 的 `TestBackend` 驗證畫面 | 列表、詳細資料、切已讀、編輯備註後 DB 正確；即時事件更新列表 |
| M14 | CLI `fax list/show/read/note/redeliver` | 輸出與 DB 一致；操作者記為 `cli:<帳號>` |
